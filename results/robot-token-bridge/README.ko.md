# 방향 토큰과 양방향 제어 규약 검사

[English](README.md) · [상세 연구 보고서](../../reports/neural-link/robotics.ko.html) · [생물학·언어모델 설계 근거](../../examples/bio_bridge/ROBOTICS_BRIDGE_RESEARCH.ko.md)

이것은 결정론적 **호스트 코덱과 1차원 운동학 검사**입니다. 언어모델·임베딩·신경 회로·생물학 실험이 아닙니다. 호스트가 명시적으로 주어진 목표 방향과 관측 방향을 읽고, 선택적으로 이산 ID로 인코딩·디코딩한 뒤 조향 명령을 보내고 다음 상태를 관측합니다. 미래 브리지에 필요한 공학적 규약을 검사하며, 일반 언어모델이 이 ID를 이해하거나 몸을 제어한다는 증거는 아닙니다.

## 방법과 결과

10개 조건마다 난수 seed 8개 × 초기 상태 16개, 총 1,280개 에피소드를 초기화하며 실행했습니다. 이는 짝지어진 합성 사례이지 독립 학습 모델이나 동물 표본이 아닙니다. 100 Hz로 3초를 적분하고 1.5초에 명시적 목표를 바꿉니다. 몸은 명령 각속도와 ±0.6 rad/s 범위에서 뽑은 일정한 외란을 합쳐 적분합니다. 제어기는 `2*sin(목표-현재방향)`입니다. PFL3 연구의 원형 방향 비교에서 영감을 얻었지만 실제 세포형·연결·신경 동역학 모델은 아닙니다.

관측에는 현재·목표 방향의 sin/cos, 출처, 시각, 직전 실제 회전과 명령 복사본이 있습니다. **제어기가 읽는 것은 방향과 목표뿐**이며 나머지 기록 필드로 forward model을 학습하거나 고유감각을 처리하지 않습니다. 자기 명령 조건에서는 외란 없이 명령만 적분한 값을 관측 방향으로 공급합니다. 명령과 실제 결과의 차이를 시험하도록 의도적으로 불완전한 상태 추정을 만든 조건입니다.

성공은 3초 시점 방향 오차가 0.15 rad(약 8.59°)보다 작은 경우입니다. 지속 안정화·자원 도달·장기 보행 성공이 아닙니다. 임계값 성공 수와 함께 평균 최종 오차를 제시하고 모든 실패를 보존했습니다.

| 조건 | 성공 | 평균 최종 오차 (rad) | 거부 명령 시도 |
|---|---:|---:|---:|
| continuous_true_disturbance | 55/128 | 0.2904 | 0 |
| bins16_true_disturbance | 49/128 | 0.3257 | 0 |
| bins64_true_disturbance | 57/128 | 0.3040 | 0 |
| bins256_true_disturbance | 56/128 | 0.2894 | 0 |
| bins64_actioncopy_disturbance | 9/128 | 0.9211 | 0 |
| bins64_wrongframe_disturbance | 8/128 | 1.4594 | 38528 |
| bins64_oneshot_disturbance | 4/128 | 1.4721 | 0 |
| bins64_slow2hz_disturbance | 50/128 | 0.3743 | 0 |
| bins64_true_no_disturbance | 88/128 | 0.1972 | 0 |
| bins64_actuator_no_effect_disturbance | 8/128 | 1.4594 | 0 |

토큰 해상도를 높인다고 성공 수가 단조 증가하지 않았습니다. 64단계는 연속값의 55/128보다 많은 57/128을 성공했지만, 평균 오차는 오히려 0.290에서 0.304 rad로 나빠졌습니다. 어느 방식의 일반적 우월성을 뜻하지 않습니다. 모델 학습·동물 집단 추론·언어 일반화 실험도 아닙니다.

## 대조군의 해석

- `wrongframe`: body 좌표계를 요구하는 수신기가 모든 명령을 거부합니다. 거부 기록 38,528개에는 마지막 관측 tick도 포함됩니다. 좌표 변환의 정량 성능이 아니라 schema 검증입니다.
- `actuator_no_effect`: 명령은 받아들이되 몸의 motor gain을 0으로 둡니다. 잘못된 좌표계 조건과 실제 궤적은 같지만 거부 수는 0입니다. 명령 수락과 실제 실행 효과를 구분합니다.
- `true_no_disturbance`: 외부 회전만 없앴으며 명령은 여전히 몸에 작용합니다. 쉬워진 환경이지 행동 인과성 제거 대조군은 아닙니다.
- `oneshot`: 첫 운동 명령이 0.25초에 만료된 뒤 출력은 0입니다. **지속 목표 기억이나 생물학적 일회 회상 비교가 아니며** 뒤의 목표 변경에 대응하지 않습니다.
- `slow2hz`: 0.5초마다 명령을 갱신하고 사이에는 유지합니다. 실제 언어모델 지연시간 측정이 아닙니다.

명령 유효 구간은 `[발행, 만료)`이며 만료·미래·중복 순번·잘못된 좌표계·비유한 값을 거부합니다. 이 진단은 호출 시각이 단조 증가한다고 가정하며 시계 역행 복구나 실사용 액추에이터 안전 범위 처리는 구현하지 않았습니다. 방향과 목표의 ID 영역은 별도이며 코덱이 허용하는 범위는 4–1,000단계입니다. 사전학습 언어모델의 어휘가 아닙니다. sine 제어 출력은 ±2 rad/s 안에 있으므로 선언된 ±2.5 clipping은 작동하지 않습니다. 액추에이터 포화 처리를 검증한 결과도 아닙니다.

두 목표는 모두 **초기 방향**과 거의 정반대일 때만 조정합니다. 목표가 바뀌는 시점의 실제 방향에는 이런 보호가 없으므로 sine 제어기의 불안정한 정반대 영점 부근에서 느리게 움직이는 사례도 결과에 남습니다.

## 발견한 오류와 보존

`../robot-token-bridge-precheck-v0/`에 첫 9조건 실행과 당시 해시가 일치하는 소스·테스트를 보존했습니다. 검사에서 만료 시각까지 포함해 명목 0.25초 명령이 실제로 26구간, 0.26초 작용하는 오류를 발견했습니다. 수정본은 만료 시각을 제외하고 경계 테스트를 추가했습니다. 일회 명령 성공 수는 여전히 4/128이지만 평균 최종 오차는 1.4728897에서 1.4720602 rad로 바뀌었습니다. 최초 잠금 파일은 결과 후 작성되어 사전 등록이 아닌 재현 출처 기록입니다.

수정 실행은 결과 계산 전에 설정·소스·테스트를 `protocol-lock.json`에 고정하고, 결과 후 `run-manifest.json`으로 변경하지 않은 잠금과 결과를 묶었습니다. **초기 결과와 검토에 영향을 받은 후속 프로토콜**이며 새로운 독립 홀드아웃이 아닙니다. 두 실행 모두 학습하지 않았습니다.

## 재현

원 실행은 Python 3.11.15, NumPy 2.4.6입니다. `requirements.txt`에 외부 의존성을 고정했습니다. 전체 약 68 MB JSON은 손실 없는 gzip으로 Git에 보존합니다. 압축 원본을 지우지 않고 복원한 뒤 검증합니다.

```sh
python3 - <<'PYRESTORE'
from pathlib import Path
import gzip, hashlib, json
p = Path('results/robot-token-bridge/results.json')
raw = gzip.decompress(p.with_suffix('.json.gz').read_bytes())
lock = json.loads(p.with_name('run-manifest.json').read_text())
assert hashlib.sha256(raw).hexdigest() == lock['results_sha256']
if p.exists():
    assert p.read_bytes() == raw
else:
    p.write_bytes(raw)
PYRESTORE
.venv/bin/python examples/bio_bridge/robot_token_bridge.py verify
PYTHONPATH=examples/bio_bridge .venv/bin/python -m unittest test_robot_token_bridge -q
```

설정·소스 잠금, 결과 해시, 전체 경로의 독립 재계산 일치를 검사합니다. 수정 전 자료도 남겼습니다. 환경은 측정 후 `runtime.json`에 기록했으며 다른 플랫폼·버전의 비트 단위 일치를 보장하지 않습니다. 새 규약 테스트 8개와 전체 관련 테스트 167개가 통과했습니다.

**임베딩·언어모델 읽기 어댑터와 학습된 쓰기 어댑터는 이 진단에서 실행하지 않았습니다.** 별도의 [FlyGym 검사](../robot-simulator-smoke/README.ko.md)는 실제 물리 시뮬레이터를 실행하지만 이 토큰 루프나 언어모델과 아직 연결하지 않았습니다. 두 요소를 연결한 학습·평가는 별도의 다음 실험입니다.
