# 대표 신호 하나 선택과 연속 사후확률 혼합 비교

[English](README.md) · [HTML 보고서](../../reports/neural-link/feedback.ko.html) · [상위 실험](../causal-feedback/README.ko.md)

여러 클래스 대표 prefix를 섞는 과정에서 명령 전달력이 떨어지는지 검토한 사후 실험입니다. 연속 피드백 실험 결과를 확인한 뒤 설계했으며, 기존 문장 64개와 고정 어댑터 3개를 재사용합니다. 새로운 홀드아웃이나 추가 학습 결과가 아닙니다.

## 변경점과 측정값

첫 FunctionGemma 출력은 동일하게 유지합니다. 이후 호스트가 실행 행동과 관측으로 베이즈 사후확률을 계산합니다. 연속 방식은 네 대표 prefix를 사후확률로 가중 혼합하고, 이산 방식은 사후확률이 가장 큰 클래스의 대표 prefix 하나를 선택합니다. 두 방식 모두 원래 입력 prefix의 노름으로 맞춥니다. 가중치·사전확률·관측 신뢰도·실행부·판단 예산은 같습니다. 이번 추가 실험은 native701 실행부와 즉시 피드백만 대상으로 합니다.

| 어댑터 | 연속 방식 성공 | 하나 선택 성공 | 개선 / 악화 사례 | 연속 평균 행동 수 | 하나 선택 평균 행동 수 |
|---|---:|---:|---:|---:|---:|
| 풀링 MLP | 52/64 | 64/64 | 12 / 0 | 2.047 | 1.828 |
| 학습 쿼리 | 52/64 | 62/64 | 11 / 1 | 1.969 | 1.844 |
| 고정 쿼리 | 45/64 | 64/64 | 19 / 0 | 2.094 | 1.766 |

하나 선택 방식의 성공 수는 첫 출력을 맞춘 호스트 베이즈 대조군 64/62/64와 같습니다. 호스트 무반복 탐색 64/63/64를 넘지 않습니다. 합계가 같다고 모든 판단 경로가 같다는 의미는 아닙니다. 호스트가 클래스를 먼저 선택하므로, 이 결과는 인터페이스 선택의 근거이지 언어모델이나 파리 회로가 추론을 학습했다는 근거가 아닙니다. 평균 행동 수에는 실패와 학습 쿼리의 잘못된 첫 함수 호출에 의한 조기 종료도 포함되어 효율의 공정한 단독 지표가 아닙니다.

## 보존한 반례

학습 쿼리의 `bilateral-water-night_shift-ko`는 악화됐습니다. 이미 충분히 잤고 현재 마른 혀를 축이고 싶다는 요청입니다. 연속 방식은 휴식 → 보온 → 물로 성공했지만 하나 선택 방식은 휴식 → 보온 → 음식 → 휴식으로 실패했습니다. 고정 관측 신뢰도 0.9를 쓰는 호스트는 실패한 행동을 제거하지 않고 확률만 줄입니다. 세 번 실패한 뒤에도 마지막 사후확률은 휴식 0.4277, 물 0.3995여서 잘못된 호스트 결정을 그대로 전달합니다. 따라서 이것은 반드시 디코더 오류라고 볼 수 없으며 제어기의 관측 모델 오류일 수 있습니다. 나머지 실패는 사례 31의 동일한 첫 출력 형식 오류로, 후속 개입 기회가 없었습니다.

이산 채널은 상위 결정의 전달을 개선하면서 그 결정의 오류도 충실하게 전달할 수 있습니다. 이번 결정론적 과제의 구조를 이용한 무반복 탐색이 더 유리합니다. 잡음·지연·목표 변경·다수 행동·실제 생물학적 과제에서는 결과가 달라질 수 있으며 이번 확장에서는 검증하지 않았습니다.

사후 경로 검사에서는 모든 후속 생성 명령이 기록된 호스트 사후확률의 argmax와 일치했습니다. 풀링 53/53, 학습 쿼리 55/55, 고정 쿼리 49/49입니다. [검사와 입력 해시](host-command-audit.json). 따라서 학습 쿼리의 이산 방식 실패는 선택된 클래스를 전달하지 못한 문제가 아니라 호스트 선택의 문제로 좁혀집니다. 기존 경로를 재분석한 것이며 추가 평가 사례가 아닙니다.

## 고정 자료와 재현

추가 디코딩 전에 `protocol-lock.json`을 고정했습니다. 최초 준비본은 전체 캐시 경로 재현 검사를 추가하기 위해 결과가 생성되기 전에 대체했습니다. `../hard-feedback-routing-predecode-v0/`에 최초 잠금 파일과 일치하는 소스 스냅샷, 변경 이유를 보존했습니다. 측정 결과를 보고 준비본을 선택하지 않았습니다.

상위 실험과 prefix 해시가 같은 경우 캐시를 재사용했고 실제 새 생성은 156회입니다. 실행 전후 원본 모델 가중치는 비트 단위로 동일합니다. `verify`는 모든 결과 해시와 3개 어댑터 × 64개 사례의 환경·호스트·prefix 전체 경로를 저장된 생성 문자열로 정확하게 재현하고 첫 원문 출력·명령 일치를 다시 검사합니다. 별도로 사전 지정된 박물관 계열 8개 사례에 도달한 새 prefix 16개(어댑터별 5/4/7)를 실제 언어모델로 재생성해 정확히 일치했습니다. 실제 재생성의 범위는 한 계열의 목표 4개 × 언어 2개이며 모든 문장·계열이 아닙니다.

```sh
.venv/bin/python examples/bio_bridge/hard_feedback_routing.py verify
```

`results.json`에 전체 경로와 사례별 비교, `generation-cache.json` 및 `new-prefixes.safetensors`에 새 생성 입력·출력, `verification.json`에 재현 결과가 있습니다. 상위 실험의 이동 가능한 번들에 포함되며 원본 Gemma 가중치는 별도로 필요합니다.
