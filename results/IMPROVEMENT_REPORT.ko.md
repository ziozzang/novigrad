# Novigrad v0.1.1 — 학습 메커니즘 개선과 새 평가 결과

[English: 전체 프로토콜·표·해석](IMPROVEMENT_REPORT.md)

같은 FlyWire 연결 구조와 입력 어댑터에서 학습 설정을 개선했다. 사전 학습 CNN·OCR이나 새 dense 레이어를 추가하지 않았다. 가장 좋은 설정은 **출력 가중치 총량 정규화 해제, 최대 75회 반복, 활성 KC 20%**였다. 기존 시냅스의 부호와 개별 가중치 한도는 유지한다. 엔진 기본값 자체를 바꾸지 않고 과제별 설정으로 선택했다.

## 이전에 사용하지 않은 데이터의 결과

| 지표 | 기존 v0.1.0 모델 | 개선 모델 3 seed 평균 | 개선 seed 범위 | 라벨 섞기 대조군 |
|---|---:|---:|---:|---:|
| 의류 8,000장 | 71.20% | **85.04%** | 84.83–85.26% | 9.24% |
| CAPTCHA 문자 4,000개 | 83.50% | **99.49%** | 99.48–99.50% | 12.53% |
| CAPTCHA 네 자리 전체 1,000장 | 49.20% | **98.00%** | 98.00–98.00% | 0.00% |

기존 모델도 **동일한 새 평가 데이터**로 다시 평가했다. 이전 릴리스에서 발표한 다른 시험 분할의 72.62%·83.32%·48.67%와 직접 섞어 비교하지 않았다. 기존 비교 대상은 배포된 seed 1 모델이며, 개선 모델은 seed 1·2·3이다. 배포할 개선 모델도 시험 점수와 무관하게 seed 1을 사용한다.

세 seed는 같은 데이터 분할을 사용하므로 그 범위가 여러 데이터셋에 대한 오차 범위를 뜻하지는 않는다. 의류 교차 엔트로피는 1.512→0.431, 문자 교차 엔트로피는 1.633→0.064로 개선됐다. 정확도가 높다고 확률이 보정된 신뢰도라거나 새로운 분포에서도 안전하게 일반화한다고 주장하지 않는다.

## 어떤 실험이 도움이 됐는가

| 설정 | 의류 검증 | CAPTCHA 문자 검증 | 판단 |
|---|---:|---:|---|
| 기존 25회 반복 | 74.65% | 84.20% | 기준 재현 |
| 출력 L1 정규화만 해제 | 86.70% | 97.95% | 가장 큰 단일 개선 |
| 정규화 유지, gain 48·학습률 역비례 조정 | 85.75% | 95.55% | 출력 크기와 학습 기울기도 중요 |
| 정규화 해제, 최대 75회 반복 | 87.85% | 99.00% | 반복 증가 효과 |
| 위 설정에서 활성 KC 20% | 88.00% | 99.30% | 최종 선택 |
| PCA 96차원, KC 10%, 75회 | 87.60% | 98.50% | 차원 증가는 도움이 안 됨 |
| 배치 16·학습률 0.0016, KC 10%, 75회 | 87.85% | 99.00% | 대응하는 온라인 방식과 동일 |
| 배치 64·학습률 0.0064, KC 20%, 75회 | 87.95% | 99.15% | 대응하는 온라인 방식보다 조금 낮음 |

![학습 곡선](improvement/learning-curves.svg)

이 표와 그림은 **검증 세트**의 seed 1 결과다. 각 실험은 시험 예측을 생성하지 않는다. 두 과제에 동일한 여덟 설정을 적용했고, 이 결과로 설정을 고정한 뒤에만 새 평가 데이터를 열었다.

L1 정규화는 MBON의 입력 가중치 절댓값 합을 1 이하로 제한한다. 한 샘플의 갱신이 한도를 넘으면 기존 가중치도 함께 축소하므로 패턴 간 경쟁이 생긴다. 이를 끄자 출력에 실을 수 있는 증거의 크기가 커졌다. 하지만 이것만이 유일한 원인이라고 단정할 수는 없다. gain을 바꾸고 재학습해도 개선되며, 이는 softmax 확률이 학습 오차 항을 바꾸기 때문이다. 이미 학습된 모델의 logit에 양수를 곱하는 것만으로는 argmax가 달라지지 않는다.

25회 시점에도 학습 곡선이 좋아지고 있어 75회까지 반복한 효과가 있었다. 늦은 시점에 나빠지면 검증 성능이 가장 좋았던 체크포인트를 선택한다. 활성 뉴런 비율 증가의 추가 이득은 작다. PCA 차원은 입력 포트에 성분을 반복 배치하는 방식도 함께 바꾸므로, 이번 실패를 모든 고차원 표현의 한계로 해석하지 않는다.

미니배치는 정확도 향상이 입증돼서 채택한 것이 아니라, 업데이트를 모아 처리하는 범용 기능으로 구현했다. 학습률은 평균 기울기 한 번의 갱신에 적용하며 자동 보정하지 않는다. 배치 크기 1은 기존 온라인 경로를 유지한다.

## 데이터와 재현성

학습 데이터는 의류 10,000장·CAPTCHA 전체 이미지 3,000장으로 유지했다. 검증 세트도 기존과 같다. 새 의류 평가는 이전 평가에 사용하지 않은 공식 시험 인덱스 8,000개다. 새 CAPTCHA 1,000개 문자열은 기존 모든 분할의 문자열을 제외하고 다른 seed로 생성했다. 학습·새 평가 간 동일 이미지 중복은 두 과제 모두 0이다.

어댑터는 학습 이미지에서만 맞추고, 추론 엔진에는 라벨을 전달하지 않는다. CAPTCHA의 글꼴·잡음 분포와 고정 셀 위치는 공유되므로 임의의 웹 CAPTCHA나 보지 않은 글꼴을 검증한 것은 아니다. 이 새 평가 세트 역시 결과가 공개됐으므로 후속 튜닝에서는 이미 관측한 자료로 취급해야 한다.

## 범용 구조에 남긴 기능

- `novi` / `novi_engine`: 이름을 Novigrad에 맞췄다. 기존 `nobi.*` 저장 형식 식별자는 호환성을 위해 읽을 수 있다.
- [미니배치·실험 도구](../docs/optimization.ko.md): 평균 기울기 누적, 잔여 배치 처리, 미완료 배치 체크포인트 거부.
- [로컬 HTTP API](../docs/api.ko.md): 포트 메타데이터·추론·선택적 학습·체크포인트. 모델별 잠금, 작업 수 제한, U64 ID의 문자열 표현.
- [주기 실행 런타임](../docs/runtime.ko.md): 버퍼 재사용, 주기 초과 측정, 놓친 슬롯 건너뛰기. Mac에서 hard RTOS를 보장하지 않는다.
- [지연 보상](../docs/neuromodulation.ko.md): 보상 예측 오차와 과거 행동 재실행을 이용하는 공학적 모듈. [27회 후각·가상 행동 실험](NEUROMODULATION_REPORT.ko.md)은 이미지 지도 학습과 별도로 검증했다.

M2 Ultra의 한 측정에서 기존 CAPTCHA 모델을 1ms 주기로 1,000회 실행한 평균 계산 시간은 약 116µs, deadline 초과는 0회였다. 이상적인 슬롯보다 시작이 늦은 경우는 1,000회 모두 기록됐다. 이 관측을 OS 스케줄링 보장으로 해석하지 않는다. API의 실제 이미지 예측도 로컬 실행 파일과 일치했다.
