# 고정 언어 모델 인터페이스의 행동 피드백 검증

[English](README.md) · [HTML 보고서](../../reports/neural-link/feedback.ko.html) · [생물학·BMI 문헌 연구](../../examples/bio_bridge/CAUSAL_FEEDBACK_RESEARCH.ko.md)

이번 질문은 좁습니다. 실행한 행동의 결과를 외부 알고리즘이 반영해 만든 연속 prefix를, 고정된 FunctionGemma가 다음 선택에 사용할 수 있는지 검사합니다. 언어 모델 자체의 학습, 보상에 따른 시냅스 학습, 초파리 인지, 게임 목적의 자율 발견을 검증하지 않습니다.

이전 대표 예시 재입력 실험은 모델의 첫 답과 비슷한 입력을 돌려주어 오답도 유지했습니다. 이번에는 실제로 실행된 행동이 관측을 결정하고, 호스트가 그 관측을 받은 뒤 다음 입력을 만듭니다. 그러나 환경은 여전히 **네 선택지 중 숨은 목표를 찾는 과제**입니다. 고정 목표·행동 예산·종료만 있으며, 연속적인 물리 세계·자원 고갈·이동·학습된 예측 모델·감각 예측 오차·도파민 예측 오차는 구현하지 않았습니다.

## 측정 결과

명령과 행동이 일치하는 native701 실행부에서 네 번 안의 성공 수입니다.

| 어댑터 | 입력 불변 | 강도 .5 | 강도 1 | 초기 사전 분포 | 대표 입력 대응 치환 | 같은 첫 출력·중복 없는 호스트 |
|---|---:|---:|---:|---:|---:|---:|
| 풀링 | 35/64 | 42/64 | 52/64 | 36/64 | 42/64 | 64/64 |
| 학습 쿼리 | 32/64 | 45/64 | 52/64 | 36/64 | 48/64 | 63/64 |
| 고정 쿼리 | 33/64 | 44/64 | 45/64 | 35/64 | 41/64 | 64/64 |

강도 1의 호스트 입력은 처음 실패한 사례를 각각 17·20·12개 교정했습니다. 평균 판단 횟수는 2.047·1.984·2.094이지만 학습 쿼리에는 첫 호출 무효로 조기 종료한 사례가 하나 있으므로 비용만으로 비교하면 안 됩니다. 성공한 사례에 한정한 수치와 무효 횟수를 함께 봐야 합니다. 자기 답 재입력과 반전 피드백의 성공은 세 어댑터 모두 입력 불변 기준선에 머물렀습니다.

같은 첫 출력 기준선은 **첫 두 어댑터의 결과를 본 뒤 설계한 사후 분석**으로, 원래 동결한 요인 실험과 분리해 해시를 남겼습니다. 첫 raw 생성과 파싱·명령을 정확히 같게 강제하고, 처음 무효면 똑같이 실패 종료한 뒤 나머지 선택만 호스트에 맡깁니다. 같은 첫 출력의 고정 신뢰도 베이즈는 64·62·64개, 중복 없는 탐색은 64·63·64개를 성공했습니다. 초기 언어 해석을 같게 해도 연속 prefix 전달의 손실이 남습니다. 학습 쿼리의 첫 무효 호출 때문에 그 비교군의 성공 상한은 64가 아니라 63입니다. [비교 경로 전체](matched-reference.json).

32개 영한 쌍을 단위로 10,000회 사후 부트스트랩한 강도 1−대응 치환의 성공 차이는 풀링 +15.63%p(95% 구간 [1.56,29.69]), 학습 쿼리 +6.25 [−3.13,15.63], 고정 쿼리 +6.25 [0,14.06]입니다. 학습·고정 쿼리에서는 올바른 의미 대응의 특별한 이점을 확립하지 못했습니다. 다중 비교 미보정·작성 사례·사후 분석 구간이며 학습 시드·토폴로지·동물·모집단에 대한 추론이 아닙니다. [그룹·쌍별 분석](posthoc-analysis.json).

강도 1의 지연/잡음 조건 성공은 각각 풀링 44/42, 학습 쿼리 47/47, 고정 쿼리 45/43입니다. 즉시 관측의 52/52/45와 비교할 수 있으며 사례마다 하나로 고정한 잡음 스케줄입니다. 호환되지 않는 native601에서는 강도 1도 27/25/18에 그쳤고, 중복 없는 호스트 탐색은 도달성 상한인 32개를 성공했습니다. 이번 제어기는 실행부의 역변환을 학습하지 않습니다.

총 84조건을 실행했으며 서로 다른 실제 언어 모델 생성은 2,926회(903/951/1,072)였습니다. 저장된 문자열로 환경·호스트·prefix 경로 전체가 정확히 재생됐고, 사전 지정한 서로 다른 생성 358회(108/95/155)도 실제 재호출에서 모두 일치했습니다. 본체 가중치의 실행 전후 메모리 해시도 같았습니다. 재현 가능한 호스트 보조 인터페이스를 보여주지만 언어 모델이나 뇌 모사 추론의 우월성을 입증하지는 않습니다.

## 사전 고정한 진단과 데이터 재사용

이전 연구의 문장 64개와 480회 학습 어댑터 세 개를 그대로 사용합니다. 이미 결과를 확인한 8개 상황 계열·32개 영한 번역 쌍입니다. 새로운 일반화 성능 평가가 아니라 사후 기전 진단으로 구분합니다. 새 학습, 하이퍼파라미터 탐색, 입력 강도 선택, 최종 결과에 따른 모델 선택은 하지 않습니다.

어댑터는 회로 풀링·학습 쿼리·고정 쿼리입니다. 원본 BF16 FunctionGemma-270M과 FP32 어댑터를 모두 고정합니다. 입력의 출발점인 EmbeddingGemma-300M과 SiteCodec601도 그대로입니다. 언어 모델을 사용하는 모든 조건의 첫 입력과 첫 생성은 같습니다. 동일 prefix의 결정적 생성은 캐시로 재사용하며 독립적인 재시도로 세지 않습니다.

실행 전에 수치 코드, 환경, 테스트, 초기·대표 prefix, 사전 분포, 문장, 실행 정책, 이전 연구의 동결·평가·검증 해시를 고정합니다. 이전 lock으로 원본 모델·설정·토크나이저·임베딩·회로·codec·어댑터도 연결해 검사합니다. 모든 생성 문자열과 행동 경로를 보존합니다.

## 구분한 네 가지 인터페이스

1. **관측:** 환경은 실제 실행 행동, 전달된 보상이 귀속되는 행동, 보상, 종료 여부, 시점을 돌려줍니다. 정책에 숨은 목표를 직접 전달하지 않습니다. 평가기는 목표를 보유하고 정답을 계산합니다.
2. **호스트의 믿음 갱신:** 초기 분포는 기존 네 함수 호출 후보의 합산 로그우도를 응답 토큰 수로 나눈 뒤 온도 1의 softmax를 적용합니다. 15·16토큰의 단순 합산 차이는 제거하지만 확률 보정이 된 것은 아닙니다. 호스트는 신뢰도 0.9인 관측 모델로 베이즈 갱신합니다. 결정적 관측과 오류율 25% 관측 모두에 같은 0.9를 사용하므로 의도적으로 완전히 맞지 않는 공통 모델입니다. 최적 정책이라고 부르지 않습니다.
3. **믿음에서 prefix로:** 기존 학습 클래스별 평균 임베딩을 회로와 어댑터에 통과시켜 얻은 네 prefix를 사용합니다. 클래스와 prefix의 대응에는 지도 정보가 있습니다. 갱신한 믿음으로 가중합하고 초기 prefix와 강도 0.5 또는 1로 섞은 뒤 초기 prefix의 norm에 맞춥니다. 외부에서 설계한 의미 자극이지 언어 모델이 사후 확률을 계산하거나 배운 것이 아닙니다. 보간된 prefix가 학습 분포 안에 있다는 보장도 없습니다.
4. **실행:** 생성한 `set_goal` 명령을 네이티브 Rust 회로가 네 기존 학습 대표 입력에서 출력한 행동으로 변환합니다. 이 결정적 표는 한 번 측정해 캐시합니다. 실행부를 바꿔도 읽기 경로의 Codec601과 언어 입력 특징은 그대로입니다. 전체 감각·운동 역학이 아니라 이 네 대표 입력의 명령→행동 변환을 검사합니다.

정책 601은 명령을 `[0,3,3,3]`으로 변환합니다. food와 warmth 행동에 도달할 수 없어, 균형 잡힌 64개 사례의 성공 상한은 판단 능력과 무관하게 32/64입니다. 정책 701은 `[0,1,2,3]`이므로 모든 목표에 도달할 수 있습니다. 두 체크포인트의 순서 있는 그래프 텐서는 같고 가소성 가중치만 다릅니다. 이전 연구의 MBON 특징까지 동시에 바뀌는 혼동을 줄였지만, 네 대표 입력의 보정이 임의의 자극에서도 유효하다는 뜻은 아닙니다.

## 조건과 측정값

각 사례는 초기화하고 최대 네 번 판단합니다. 실제 실행 행동이 맞으면 성공으로 종료합니다. 행동당 비용은 0.05이며, 전달되는 관측 보상은 성공 표시 0.95·실패 표시 −0.05입니다. 생성이 유효하지 않으면 실제 행동 없이 실패 종료합니다. 물리적 효용은 성공 여부에서 행동 비용을 뺍니다. 무효 출력의 조기 종료가 비용만 보면 유리해 보일 수 있으므로 비용이나 효용만으로 우열을 정하면 안 됩니다. 성공한 사례에 한정한 판단 횟수도 별도로 보고하되 선택 편향이 있습니다.

실제 언어 모델 조건:

- `original`: 매번 초기 prefix를 그대로 사용합니다. 결정적인 입력 불변 기준선입니다.
- `self_writeback`: 실행 행동·결과가 아니라 **명령한** 목표의 대표 prefix를 돌려줍니다. 자기확증 대조군입니다.
- `belief_half`, `belief_full`: 호스트가 갱신한 믿음으로 강도 0.5·1의 입력을 만듭니다.
- `static_prior_prefix`: 첫 행동 뒤 초기 사전 분포로만 대표 prefix를 섞습니다. 결과를 반영하지 않지만 초기 입력 그대로인 조건과는 다릅니다.
- `flipped_feedback`: 호스트에 전달하는 보상 표시만 뒤집고 호스트에는 이를 알리지 않습니다.
- `permuted_prototypes`: 사후 확률과 대표 prefix의 대응을 고정된 순환 치환으로 바꿉니다.
- `uniform_prefix`: 첫 행동 뒤 네 대표 prefix의 같은 비율 혼합을 사용합니다.

별도의 호스트 기준선은 언어 모델을 우회합니다. `analytic_fixed_model`은 호스트 사후 확률이 가장 큰 행동을 고릅니다. `prior_ranked_no_repeat`는 초기 사전 확률 순서대로 명령을 한 번씩만 시도하며, 행동 선택에 결과를 사용하지 않습니다. 실행부가 맞는 결정적 네 선택지 과제라면 후자는 **피드백 없이도 네 번 안에 전부 성공**할 수 있습니다. 따라서 최종 성공률만으로 피드백이나 언어 모델의 특별한 능력을 입증할 수 없습니다. 예산별 성공률, 첫 오류의 교정, 무효 호출, 실행 행동 반복, 비용을 함께 봅니다.

모든 언어 모델 조건은 첫 판단이 같고 실제 정답이면 즉시 끝납니다. 따라서 누적 성공률이 초기 입력 불변 기준선보다 낮아질 수 없는 구조입니다. 정답 뒤의 불안정화는 검사하지 못합니다. 단지 시도 기회가 늘어도 균등·치환 입력에서 성공이 늘 수 있습니다. 초기 사전 분포·대응 치환·중복 없는 탐색과의 비교가 핵심이며, `original`보다 좋아졌다는 사실만으로 정보에 특이적인 피드백 효과를 입증할 수 없습니다.

열 조건 모두 즉시 피드백과 두 실행부에서 실행합니다. 추가 지연 1회·보상 오류율 25% 조건은 `belief_full`과 `analytic_fixed_model`만 실행합니다. 잡음은 사례·행동 시점별로 미리 같은 난수로 정합니다. 지연된 관측에는 원래 실행 행동의 ID를 유지해 현재 명령에 잘못 보상을 주지 않습니다. 이 제한된 잡음 실험으로 열 조건 전체의 견고성 순위를 말할 수 없습니다.

보상이 지연되거나 뒤집혀도 실제 성공이면 종료합니다. 실제 성공 보상을 받은 뒤의 다음 판단은 없으므로, 주로 종료 전 실패 관측에 대한 반응을 검사하며 양성 보상 학습을 검사하지 않습니다. 종료 정보가 실제 성공을 알려주므로 완전히 가려진 기만 실험은 아닙니다. 실패 뒤 거짓 양성 보상은 계속 진행하지만, 성공 뒤 거짓 음성 보상은 즉시 끝납니다.

## 재현

```sh
.venv/bin/python examples/bio_bridge/causal_feedback.py verify
.venv/bin/python -m unittest discover -s examples/bio_bridge -p 'test_*.py' -q
.venv/bin/python examples/bio_bridge/analyze_feedback.py
.venv/bin/python reports/neural-link/build_feedback_report.py
```

분석기는 기존 결과를 덮어쓰지 않습니다. 발표한 lock과 결과를 지워 재실행하지 마세요. 새 실험은 분리된 출력 위치에서 `prepare`, `run`, `verify` 순으로 진행합니다.

검증은 두 층입니다. 저장된 생성 문자열로 환경·호스트·prefix 계산 전체를 재생하고, 사전 지정한 8개 사례(museum 계열의 네 목표×두 언어이며 전체 상황 계열을 포괄하지 않음)가 모든 조건에서 실제 사용한 서로 다른 prefix는 고정 언어 모델에서 다시 생성합니다. 64개 전체의 모든 prefix를 다시 생성했다는 뜻은 아닙니다. 파일 해시와 실행 전후 본체 메모리 해시를 검사하며 시간 측정은 정확도 기준으로 쓰지 않습니다. Mac MPS 실험이며 처리량이나 하드 실시간 보장 시험이 아닙니다.

## 생물학적 해석

초파리 버섯체의 도파민 연구는 기대한 결과와 실제 결과를 구분할 필요를, 운동 명령 복사 연구는 명령의 복사본과 실제 감각 결과를 구분할 필요를 뒷받침합니다. 그렇다고 호스트의 베이즈 계산, 네 개의 지도된 대표 입력, Novi의 모의 발화율이 그 생물학적 기전이라고 볼 수는 없습니다. 문헌 문서는 이번 구현과 더 강한 후속 제안을 구분합니다. 실제 신경 기록, 확인된 신경 구획, 측정된 행동, 생물학적 인과 개입은 없습니다.

호스트 도움으로 오류가 줄더라도 그 결과는 이 인터페이스를 통한 고정 언어 모델 조종을 보여줍니다. 언어 모델이나 뇌 모사 회로에 추가 능력을 귀속하려면 관측 조건이 같은 분석적·탐색 기준선보다 낫거나, 그 기준선에 없는 정보 처리를 보여야 합니다. 동적 환경, 행동과 결과의 연결을 끊는 대조군, 학습된 예측 모델, 외부 신경·행동 데이터는 별도 후속 실험입니다.

## 대표 신호 하나를 선택하는 후속 실험

별도 잠금한 **사후 실험**에서 사후확률 가중 혼합을 호스트 argmax가 선택한 대표 신호 하나로 바꿨습니다. 호환 실행부·즉시 피드백 성공 수가 52/52/45에서 64/62/64로 증가했습니다. 학습 쿼리는 개선 11건과 악화 1건이 있으며, 잘못 설정된 호스트 관측 모델은 이미 실패한 행동을 반복할 수 있습니다. 성공 수는 같은 첫 출력을 쓰는 호스트 베이즈와 같고 무반복 호스트 탐색을 넘지 못합니다. [전체 방법·반례·정확 재현](../hard-feedback-routing/README.ko.md).

## 이동 가능한 번들

날짜가 붙은 `novigrad-feedback-20260918.tar.gz`는 [v0.1.1 릴리즈 자료](https://github.com/ziozzang/novigrad/releases/tag/v0.1.1)에 배포할 자료입니다. 기존 양방향 번들을 변경 없이 포함하고, 이번 실험·관측 잡음·하나 선택 실험의 결과, Safetensors 입력, 소스, 보고서, 콘텐츠 명세를 추가합니다. 원본 Gemma 가중치와 플랫폼별 네이티브 라이브러리는 제외합니다.

```sh
python3 scripts/package_feedback.py unpack novigrad-feedback-20260918.tar.gz /new/path/feedback-replay
cd /new/path/feedback-replay
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-gemma.txt -r requirements-functiongemma.txt scipy==1.17.1
.venv/bin/python -m pip install .
.venv/bin/python examples/bio_bridge/replay_feedback.py --embedding-model /local/embeddinggemma --function-model /local/functiongemma --include-hard-routing --check-only
.venv/bin/python examples/bio_bridge/replay_feedback.py --embedding-model /local/embeddinggemma --function-model /local/functiongemma --include-hard-routing
```

압축 해제 명령은 저장소 체크아웃에서 실행하며 목적지는 아직 없는 경로여야 합니다. 모델 디렉터리의 내용은 기존 해시와 대조하고 경로 조회만 변경합니다. 실제 재생성은 기존 Mac MPS 정밀도·실행 환경을 전제합니다. 별도의 관측 잡음 검증기는 원래 네이티브 공유 라이브러리 해시도 고정하므로 소스가 같더라도 새로 빌드한 wheel은 그 엄격한 지문 검사를 통과하지 못할 수 있습니다. 원본 80개 텐서는 정확히 재현했지만 바이너리에 독립적인 이식 재현을 보장하지 않습니다. 배포 검증은 압축 해제 후 기존 실행 환경으로 경로를 옮긴 언어모델을 재생합니다. 깨끗한 환경에서의 의존성 설치나 다른 플랫폼 동등성 검증과는 구분합니다.

### 실행 시 채팅 템플릿 출처 보완

원래 모델 잠금 목록에 있는 파일만 새 디렉터리로 옮긴 첫 실제 재현은 실패했습니다. 기존 목록의 확장자 필터가 FunctionGemma의 `chat_template.jinja`를 누락해서 토크나이저에 채팅 템플릿이 없었습니다. 원래 위치에서 실행할 때는 이 파일이 존재했습니다. 실패를 `portable-template-audit.json`에 보존하고, 이동 경로 재현 도구가 검사하는 별도 실행 의존성 잠금을 추가합니다. 원본 가중치와 수치 결과는 바꾸지 않습니다.

**템플릿 해시는 결과를 본 뒤 고정한 것이며 실행 전 고정이 아닙니다.** 이 보완으로 원래 고정 시점의 템플릿 동일성을 소급 입증할 수는 없습니다. 이후 정확한 재생성은 현재 잠금한 템플릿과 결과의 일관성을 검사합니다. 원래 모델 잠금 목록의 파일만 복사하지 말고 `chat_template.jinja`를 포함한 일치하는 전체 토크나이저 파일을 제공해야 합니다.
