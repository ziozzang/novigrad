# Python / Metal 성능 실험

Apple M2 Ultra, macOS 26.5, MLX 0.32.2에서 실제 측정했습니다. Python 바인딩은 Rust 엔진을 직접 호출하고, 선택적인 GPU 경로는 MLX와 순서 보존 희소 Metal 커널을 사용합니다.

| 배치 크기 | CPU 중앙값 ms | Metal 중앙값 ms | 가속 비율 |
|---:|---:|---:|---:|
| 1 | 0.111 | 1.235 | 0.09배 |
| 8 | 0.847 | 1.282 | 0.66배 |
| 32 | 3.373 | 1.455 | 2.32배 |
| 128 | 13.474 | 2.191 | 6.15배 |
| 256 | 27.527 | 3.192 | 8.62배 |

50회 반복, 준비된 Python 리스트 입력부터 리스트 결과까지 GPU 동기화와 전송을 포함했습니다. 모델 로딩과 특징 추출은 제외했습니다. 첫 GPU 호출은 약 142ms였고 셰이더 캐시가 이미 존재할 수 있습니다. 단일 관측은 CPU, 여러 독립 환경의 배치는 GPU가 적합했습니다. 순차 관측을 모으기 위한 대기 시간은 별도로 고려해야 합니다.

Fashion 특징 1,024개에서 최대 확률 오차는 2.3842e-7, argmax 차이는 0개였습니다. 모든 입력에 대한 동치 보장은 아닙니다. 밀집 행렬 방식은 확률 오차가 약 0.0122까지 발생하여 채택하지 않았습니다. 시냅스 누적 순서와 동률 선택을 보존하는 희소 커널을 적용했습니다. partition 기반 선택도 비교했지만 정렬보다 느려 채택하지 않았습니다.

CPU 학습은 배치 1/32/128에서 중앙값 0.237/5.322/21.121ms였습니다. 매 호출마다 임시 모델을 업데이트하는 비용 측정이며 학습 성능 평가가 아닙니다. 별도 HTTP 비교에서는 단일 호출 평균이 0.423ms에서 네이티브 0.103ms로 줄었고, 동일 학습 업데이트의 가중치가 정확히 일치했습니다.

GPU 학습, MLX-C 직접 연동, 자동 CPU/GPU 선택은 아직 구현하지 않았습니다. GPU 모델은 스냅샷이므로 CPU 학습 후 저장하고 다시 로드해야 합니다. 전력 소모는 측정하지 않았으며 하드 실시간 보장이 아닙니다.
