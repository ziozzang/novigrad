# 외부 데이터로 작은 조향 모방 실험

시험 정확도는 **60%(30/50)**, 항상 직진하는 기준선과 라벨 섞기 대조군은 **58%(29/50)**였습니다. 검증 정확도는 학습 전 50%에서 70%로 올랐지만, 시험에서 왼쪽 0/8·직진 29/29·오른쪽 1/13을 맞춰 대부분 직진만 예측했습니다. 균형 정확도는 35.90%이며 조향 MAE는 상수 기준선 0.21571에서 0.20421로 약 5.3% 줄었습니다. **연결·학습·저장·추론은 동작하지만, 유의미한 조향 일반화는 아직 입증하지 못했습니다.**

출력 가중치 정규화를 켠 설정이 검증에서 선택됐습니다(21 epoch). 끈 설정은 62%에 머물렀습니다. 의류·CAPTCHA에서 좋았던 설정이 작은 주행 표본에 그대로 통하지는 않았습니다. 선택된 학습 실행은 M2 Ultra에서 0.883초였으며 다운로드·어댑터·대조군 시간은 제외합니다. 시험 결과를 보고 추가 설정을 고르지는 않았습니다.

다운로드 제한 중에는 캐시의 네 세션을 58/20/31장으로 나눈 보조 실험도 실행했습니다(정확도 61.29%, 라벨 섞기 51.61%). 이는 별도 편의 표본이며 공식 분할 결과의 독립 반복 검증은 아닙니다. 두 실험의 설정 후보는 동일했습니다.

목표는 전방 카메라 영상에서 세 가지 조향 명령을 흉내 내는 것입니다. 기존 엔진에 다른 감각·행동 과제를 연결할 수 있는지 확인하는 작은 예제이며, 완성된 자율주행 시스템은 아닙니다.

데이터는 [URJC DeepRacer CARLA expert racing](https://huggingface.co/datasets/urjc-deepracer/carla-expert-racing)의 `4f993c8f052a9c94fcabbe4da63fc3eacf097c18` 리비전입니다. 게시자의 라이선스 표기는 Apache-2.0입니다. 원본 학습·검증·시험 세트는 20,697/18,623/7,776장이며 주행 세션 ID 10/10/4개가 서로 겹치지 않습니다.

처음에는 등간격 300/150/150장을 계획했지만 학습 영상 109장 뒤 뷰어가 HTTP 429 요청 제한을 반환했습니다. 작은 예제에 맞춰 최종적으로 100/50/50장을 사용합니다. 학습은 원래 300개 등간격 위치 중 처음 100개, 검증·시험은 미리 정한 100행 블록 두 개에서 각각 25장을 등간격으로 뽑습니다. 라벨을 보고 선택하지 않지만, 데이터 전체를 대표하는 표본은 아닙니다. 정확한 행과 세션은 manifest에 기록합니다. 전체 Parquet 대신 Hugging Face 뷰어의 파생 JPEG를 받습니다. 다운로드 스크립트는 모든 이미지 주소의 리비전·행 번호를 확인하고 JPEG 체크섬, 원본 행, 세션을 기록합니다. 세트 간 동일 JPEG와 세션 중복도 검사합니다. 원본 리비전이 바뀌면 자동으로 다른 자료를 쓰지 않고 중단합니다.

입력은 전체 영상을 흑백 28×28로 줄인 픽셀뿐입니다. 학습 영상만으로 HOG·풀링·PCA 어댑터를 맞춰 319개 입력률을 만듭니다. 기존 PN→KC→MBON 희소 회로와 출력 읽기 경로를 사용하며, 사전 학습된 주행 모델은 사용하지 않습니다. 조향 값은 정답으로만 쓰고 정답에서 파생된 maneuver, 마스크, 속도, 시간, 세션 ID는 입력하지 않습니다.

조향 값이 -0.2 미만이면 왼쪽, +0.2 초과이면 오른쪽, 나머지는 직진으로 분류합니다. 최대 25 epoch·patience 5·seed 1로 두 설정을 비교합니다. PCA 64개, whitening 0.5, 활성 비율 0.2, gain 12, 학습률 0.0001, batch 1, opponent 출력은 동일하고 출력별 가중치 합 정규화만 켜거나 끕니다. 검증 정확도와 교차 엔트로피로 설정을 선택해 기록한 후 시험 데이터를 추론합니다. 라벨을 섞은 학습 대조군도 포함합니다.

정확도 외에 클래스별 재현율 평균, 혼동행렬, 세션별 정확도를 기록합니다. 학습 세트의 각 클래스 평균 조향에 예측 확률을 곱하면 거친 연속 조향 값을 얻습니다. MAE 단위는 정규화된 조향 값이며 각도가 아닙니다. 항상 학습 세트 조향 중앙값을 내거나 가장 흔한 클래스를 내는 기준선과 비교합니다.

이는 작은 표본·단일 seed 결과입니다. 세션 ID가 달라도 같은 트랙이나 환경일 수 있고 세션 내부 프레임은 상관됩니다. 예측 행동이 다음 관측을 바꾸는 폐루프 시험, 충돌 회피, 실수 후 복구, 보상 기반 주행 개선은 검증하지 않습니다. 좌·우 확률이 비슷하면 확률 가중 조향은 중립처럼 보일 수 있으므로 확률 벡터도 함께 유지해야 합니다.

[영문 상세 보고서](STEERING_REPORT.md)와 [실행 예제](../examples/steering/README.md)에 결과·재현·로컬 및 API 추론 명령을 기록합니다.

## 실시간 처리 가능성

기존 API 모델과 입력 어댑터·HTTP 연결을 계속 유지한 채 30 FPS로 300회 재생했습니다. M2 Ultra에서 전체 처리 지연은 **평균 2.765ms, p95 3.211ms, p99 3.380ms, 최대 3.481ms**였습니다. 33.333ms 주기를 초과하거나 슬롯을 건너뛴 경우는 0회입니다. OS가 늦게 실행을 시작한 시간은 최대 5.038ms로 별도 기록했습니다.

JPEG 읽기·변환, 특징 인코딩, JSON/HTTP 추론, 응답 확인과 조향 디코딩을 포함합니다. 초기 로딩·준비 실행 10회·주기 대기는 제외하며 파일 캐시가 준비된 상태일 수 있습니다. 시험 영상 50장을 반복 재생해 행동이 다음 영상에 영향을 주지 않습니다. 따라서 이 관측은 **30 FPS 소프트웨어 처리 경로에 여유가 있음**을 보여 주지만 실제 카메라→액추에이터 지연이나 hard real-time을 보장하지 않습니다. 현재는 속도보다 조향 품질 개선이 더 큰 과제입니다.

[타이밍 원시 결과](steering/realtime30/summary.json), [프레임별 기록](steering/realtime30/ticks.csv), [실행 예제](../examples/steering/README.md#paced-replay-at-30-fps)를 남겼습니다. 단일 영상의 로컬·HTTP 예측 확률 차이는 1.36e-10 이하였고 Python 테스트 10개가 통과했습니다. Rust 엔진 수정 없이 같은 입출력 경로를 사용했습니다.
