# 사례별 회로·API 연구

세 층을 구분합니다: 자연어를 올바른 API로 바꾸는가, API가 실제로 원하는 상태 변화를 만드는가, 해당 계산에 생물학적 근거가 있는가. 어느 한 층의 성공이 다른 층까지 증명하지는 않습니다.

| 사례 | 근거와 실험 상태 |
|---|---|
| 목표 변경 | FC2 목표·EPG 방향·PFL3 비교에 근거. 별도 목표 각도를 중간에 바꾸는 소프트웨어 제어 실험 실행. |
| 단서 소실 | 방향 기억과 자기운동 갱신에 근거. 시각 단서가 사라질 때 odometry 유무 비교 실행. |
| 단서 충돌 | 신뢰도에 따른 감각 결합에 근거. 잘못된 시각 단서를 낮게 가중하는 방식과 고정 신뢰 방식 비교 실행. |
| 배고픔과 위험의 충돌 | 배고픔·맛·경험에 따른 선택 연구에 근거. 팩토리얼 학습 실험은 아직 설계 단계. |
| 규칙 반전 | 도파민 세포별 기억 갱신과 소거 연구 참고. 기존 Gemma→novi 실험에서 실패와 개선 조건을 모두 기록. |
| API 호출 | FunctionGemma를 실제 실행해 문법·의미·상태 오류를 분리. 실제 HTTP와 novi 판단까지 연결. |

단서 소실 구간의 방향 오차는 자기운동 갱신이 있으면 약 5.03°, 없으면 52.19°였습니다. 잘못된 시각 단서는 신뢰도를 낮추면 약 27.17°, 그대로 신뢰하면 114.48°였습니다. **신뢰도는 호스트가 알려준 값**이며 모델이 신뢰도를 발견한 결과가 아닙니다. 이 제어기는 단일 원형 상태 변수와 비례 제어기이며 실제 FC2·EPG·PFL 뉴런의 재현도 아닙니다.

FunctionGemma에는 고수준 목표와 행동 요청을 맡기고, 실제 센서·보상은 환경이 소유하는 설계가 적절합니다. 매 제어 tick마다 자연어 생성을 수행할 필요는 없습니다. 모델이 보고한 방향은 검증되지 않은 사용자 보고값으로 표시하고 실제 센서와 섞지 않았습니다.

호출 문법이 맞아도 의도가 틀릴 수 있습니다. 현재 작은 모델의 한국어·간접 표현 오류 때문에 일반적인 자율 제어가 완성됐다고 말할 수 없습니다. 일반 제어기와 작은 정책망을 계속 대조군으로 유지해야 합니다.
