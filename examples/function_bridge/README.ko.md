# FunctionGemma로 novi API 호출

**실제 FunctionGemma 생성 → 검증 → 로컬 HTTP API → novi 행동 → 환경 보상**까지 구현·실행했습니다. 원본은 BF16으로 유지하고 추가 양자화하지 않았습니다. 선택적인 LoRA는 별도 Safetensors 어댑터로 저장됩니다.

| 검증 | 원본 | LoRA |
|---|---:|---:|
| 명시적 개발 요청 | 8/8 | 8/8 |
| 학습 전 고정한 새 영어·한국어 요청 | 6/16 | 13/16 |
| 실제 HTTP와 novi를 거친 네 가지 목표 | 4/4 | 4/4 |

호출 함수와 인자가 모두 맞아야 정답입니다. 작은 수작업 데이터·한 학습 seed의 결과이므로 일반적인 신뢰성을 보장하지 않습니다. 학습은 76개 별도 예제, 80스텝, 약 37만 개 LoRA 파라미터만 사용했습니다. 원본 파일은 유지되지만 어댑터 적용 후 행동은 원본과 달라집니다.

함수는 `set_goal`, `observe_heading`, `choose_action`, `get_status`입니다. `/v1/call`로 호출할 수 있습니다. 모델이 보고한 방향은 검증되지 않은 사용자 보고값으로 표시합니다. 실제 환경 보상은 별도 토큰이 필요한 환경 전용 경로로만 받고, 모델의 도구 목록에 넣지 않았습니다.

초기 0/8은 모델 판단이 아니라 출력 경계 토큰을 처리하지 못한 파서 오류였습니다. 이를 고친 뒤 명시적 요청은 8/8이 됐습니다. 어려운 기존 사례에서는 설명 보강이 7/16→9/16으로 개선했지만, few-shot은 예제의 30도를 복사해 6/16으로 악화됐습니다. 실패 결과도 보존했습니다.

지원하지 않는 요청 4개 중 올바른 거부는 2개뿐이었습니다. 나머지는 상태 조회를 호출했으므로 보상 조작·파일 삭제는 실행되지 않았지만, 의미상 정답도 아닙니다. 문법 검증만으로 의도 오류를 막을 수 없습니다.

별도 제어 사례에서는 목표 변경, 시각 단서 소실, 자기운동 갱신, 잘못된 단서의 신뢰도 가중을 검증했습니다. 이는 공학적 원형 상태 추정기이며 실제 파리 뉴런이나 LLM 결합 제어의 재현은 아닙니다.

추가 검증 범위: 방향 입력은 현재 novi 행동 선택에 사용되지 않습니다. Live 보상은 외부 환경 성과가 아닌 목표와 행동 의미의 일치 검사이며 네 에피소드는 순차 학습합니다. Fresh 세트도 동일 작성자가 만든 소규모 평가로 독립 블라인드 검증이 아닙니다. 학습 도중 일부 상태 변경 후 예외가 발생하면 재시도는 트랜잭션 안전성을 보장하지 않습니다.
